# Individual Assignment 1 — Basic Matrix Multiplication in Different Languages

**Author:** Adrián Rodríguez Pérez · Big Data, Grado en Ciencia e Ingeniería de Datos (ULPGC), 2026-2027

Research question: *How do the runtime and peak memory of the basic triple-loop matrix multiplication
grow with the matrix size n in C, Java and Python?*

This repository contains the report, the code, configuration, raw measurements, analysis scripts and
figures of the study. The submitted `Assignment01_Adrian_Rodriguez_Materials.zip` has exactly the same
contents. Run every command below from the folder that contains `config.json` and `scripts/` (the
repository root, or the folder where either zip was extracted).

## Requirements (versions used)

- **OS:** Windows 11. The memory metric (`peak_wset`, the Windows peak working set) exists only on
  Windows; the rest of the code is portable. Keep the files in a reasonably short path: Windows'
  260-character path limit can stop Python from finding `scripts/common.py` in very deep folders.
- **C:** GCC 16.2.0 from MSYS2 UCRT64, available on `PATH` as `gcc` (e.g. add `C:\msys64\ucrt64\bin`
  to `PATH`), or change `c_compiler` in `config.json`.
- **Java:** OpenJDK 21.0.10 (Eclipse Temurin), `java` and `javac` on `PATH`.
- **Python:** CPython 3.12.0 and the packages in `requirements.txt` (NumPy 2.3.5, pandas 3.0.1,
  matplotlib 3.10.8, psutil 7.2.2). NumPy is used only to generate the inputs and to validate the
  results, never in the timed kernel; psutil reads the peak working set.

## Build and run

From the folder that contains `config.json` and `scripts/`:

```bash
pip install -r requirements.txt
python scripts/run_all.py
```

`run_all.py` takes about 25 minutes on the machine described in the report. The same steps, one by one:

```bash
python scripts/build.py
python scripts/gen_inputs.py
python scripts/env_info.py
python scripts/run_benchmarks.py
python scripts/validate.py
python scripts/analyze.py
```

The supplementary layout diagnostic (about 3 minutes) is run separately:

```bash
python scripts/run_probe.py
```

`run_benchmarks.py` accepts `--sizes` and `--langs` for partial runs, e.g.
`python scripts/run_benchmarks.py --sizes 100 200 --langs c java`.

Exact commands used by the scripts for each implementation (`config.json` holds the flags):

```bash
gcc -O2 -std=c11 -ffp-contract=off -o build/matmul_c.exe src/c/matmul.c
javac --release 21 -d build/java src/java/MatMul.java
build/matmul_c.exe <n> <A.bin> <B.bin> <warmups> <reps> <out.bin> --hold
java -Xmx4g -cp build/java MatMul <n> <A.bin> <B.bin> <warmups> <reps> <out.bin> --hold
python src/python/matmul.py <n> <A.bin> <B.bin> <warmups> <reps> <out.bin> --hold
```

Each implementation also has a self-test with known results: `build/matmul_c.exe --selftest`,
`java -cp build/java MatMul --selftest`, `python src/python/matmul.py --selftest`.

## Inputs

The input matrices are not included because of their size (≈ 300 MB). They are regenerated with:

```bash
python scripts/gen_inputs.py
```

which writes `data/inputs/A_<n>.bin` and `data/inputs/B_<n>.bin` for every size in `config.json`.
For each n, A and B are drawn from NumPy's PCG64 generator seeded with `[2026, n]`, uniform in
[−1, 1), and stored as raw little-endian row-major `float64` (8n² bytes per file, no header). All
three implementations read these same files.

`results/inputs_manifest.csv` holds the SHA-256 of every input file used in the study. When it is
present, `gen_inputs.py` does not overwrite it: it compares the regenerated files with it and prints,
for each size, whether they are identical, so anyone can confirm they obtained exactly the same inputs.
